|---|---|---|
| base.en | 8/12 | 7/12 |
| small.en | 9/12 | 8/12 |

"ElevenLabs" was transcribed as "11 Labs" by every model — a correct transcription of the audio, so excluding it: base 8/11, small 9/11, turbo 10/11 on the `say` clip. `--no-project`, `--provider`, `MCP`, `ponytail`, `sha256`, and the numbers were right everywhere. Base's misses (`pyproject` → "pipe project", `repository root` → "route", `resolve_provider_settings` mangled) are fixed by small. Turbo was the only model to spell "Kokoro". **Not the owner's voice** — the real-voice take remains a manual check.

## Apple on-device recognizer

- A bare `swiftc` CLI aborts in `SFSpeechRecognizer.requestAuthorization` (needs `NSSpeechRecognitionUsageDescription` in a bundle).
- An ad-hoc-signed bundle launched with `open -a` gets the permission prompt; `isAvailable = true`, `supportsOnDeviceRecognition = true`.
- Recognition with `requiresOnDeviceRecognition = true` returns **"Siri and Dictation are disabled"** in 0.6 s: Dictation is switched off in System Settings on the reference Mac. Not evaluable without a user settings change. Branch closed for now.

## Microphone

- Default input was a pair of unworn Bluetooth earbuds → **digital silence** (RMS 0.000000). Naming the built-in microphone explicitly gave real audio (RMS 0.0011). Device selection is therefore in scope, and the RMS pre-flight is essential.
- Bare CLI from a shell: no prompt observed; `notDetermined → authorized` transition happened silently (grant attributed to the responsible process).
- Ad-hoc-signed bundle via `open -a`: first launch stalled ~150 s inside `AVCaptureDeviceInput` while the permission dialog was answered, then `authorized` with the bundle's own identity; ~0.9 s launch overhead afterwards; real audio captured.
- Temporary Quick Action invoked with `automator` (parent `com.apple.automator.runner.xpc`): both the bare CLI and the bundle recorded real audio — but permission was already granted by then, so the first-run grant from a Service is proven only for the bundle path. `automator` is not the real `WorkflowServiceRunner.xpc`; the end-to-end first-run check is a manual step with the owner present. Temporary Service removed afterwards.
- `AVCaptureAudioFileOutput` wrote 48 kHz float32 WAVE-extensible (format tag 65534, rejected by Python's `wave`) when a device was named explicitly; `AVAudioRecorder` honored the 16 kHz/Int16 settings. The shipped recorder must assert the format or pass through `afconvert`.

## Memory under load

Baseline with Claude Code running: 1,550 MB swap used, 42% free. First cold load of small.en caused one 180 MB swap-out; every later transcription at every size caused **zero swap-outs**; free memory dipped to 28–35% during a transcription and recovered in seconds.

## Verdict against the bar

| Bar | Result |
|---|---|
| ≤ 3 s stop-to-text for 20 s of speech | pass — ~1.3 s (small.en) |
| ≤ 1.2 GB peak RSS | pass — 685–774 MB |
| No swap growth in steady state | pass — one 180 MB swap-out on first cold load only |
| Jargon no worse than base.en | pass — small beats base on both clips |

**Recommendation adopted (DEC-002):** whisper.cpp via `pywhispercpp`, default `small.en`, turbo and base kept in the manifest; recorder as the signed bundle (DEC-001); no resident worker; Metal warm-up in the install selftest; input-device selection added to the recorder contract.
