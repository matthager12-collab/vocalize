# Adversarial review: vocalize 0.12.0 (T-51)

**Date:** 2026-09-07
**Scope:** branch `local-first` at `03b991b` against `origin/main` at `c03cf94` — Phases 1-5 of `docs/plans/2026-09-app-roadmap/plan.md`: the local-first default chain, whisper.cpp beam search and the `large-v3-turbo-q5_0` default model, `vocalize/llm.py` (cloud cleanup pass over dictated transcripts, two backends), `auth._SecurityKeychain` (macOS keychain driven through `/usr/bin/security`), and the Anthropic key slot across the CLI and the config portal (`vocalize/portal.py`, `vocalize/assets/portal.js`).
**Lenses:** vocalize/llm.py and its callers (dictate.py cleanup path, hooks/speak_options.py); auth._SecurityKeychain and auth.py store/read/delete/validated_on; portal auth routes (login / test / remove / keys state) and the Keys tab; config / wizard / cli-plumbing / chain-fallback; release artifact and supply chain.
**Process:** every finding was put to three independent refuters with evidence of their own (a real keychain, a live portal on 127.0.0.1, the real `security` and `claude` binaries, a rebuilt sdist and wheel, or a red-then-green test). A finding entered the table below as **confirmed** only when at least two refuters could not refute it; a finding a majority of refuters refuted is recorded as **refuted**, with the reason, rather than dropped.

## What each lens checked and found clean

### vocalize/llm.py and its callers (dictate.py cleanup path, hooks/speak_options.py)

- Full lens suite green: `tests/test_llm.py` 32 passed; `tests/test_speak_options.py` + `tests/test_dictate.py` + `tests/test_config.py` 332 passed; `ruff check vocalize hooks tests` clean.
- The transcript never reaches argv on either backend — only `input=text` on claude-cli, only the HTTP body on anthropic; the pinned `assert TRANSCRIPT not in url` holds.
- The API key never reaches the claude child's argv or environment: `_claude_env()` pops `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and `ANTHROPIC_BASE_URL`, and `_claude_cli` never references the key at all.
- The key is not echoed on any anthropic response-failure path: `_skipped` is passed only the exception class name, an HTTP status, "unreadable reply", or a stop_reason — never the raw body or headers, checked with an ANSI-escape-and-canary-bearing 401 body.
- The egress line prints exactly once per send and only for a real send — confirmed live that the count of "vocalize: sent to anthropic" on stderr equals the number of `_http.request` calls, never more, across `off`, `local`, missing-binary, missing-key and budget-gate branches, all of which return before the line prints.
- The claude child runs outside the caller's project (a real fake `claude` reports the per-user private temp directory as its cwd, not the worktree); redirecting `TMPDIR` after `tempfile.gettempdir()` has already cached its value does not move it.
- `--setting-sources ""`, `--disallowedTools '*'` and `--strict-mcp-config` all parse on the installed Claude Code 2.1.227 (`echo hi | claude ... --version` exits 0), so the argv cannot fail the backend at parse time; whether `*` denies every tool at run time was not re-verified live (needs a real model call) and rests on the earlier review's "Verified" comment.
- Model output is sanitized before reaching a clipboard or terminal on both backends: `dictate.sanitize` drops every non-printable except `\n`/`\t`, including bidi overrides and zero-width joiners; pinned by an existing escape-sequence test.
- The anthropic response is bounded and shape-checked: a 50 MB body cap (including the error-body path), a caught `json.loads` failure, and a guarded content-block walk that degrades to `None` rather than raising on a malformed shape; redirects are refused outright and non-HTTPS URLs are refused before any request.
- Timeouts kill the child (`subprocess.run(..., timeout=...)`), and per-feature timeout/token limits are distinct and pinned (cleanup vs. notes).
- The data-boundary sentence is appended exactly once, in the one place both backends pass through, and reaches both the `--append-system-prompt` argument and the anthropic `system` field.
- `[stt] cleanup` cannot be bypassed by a legacy or malformed value: the validator, the bool-coercion path, and `llm._complete`'s own closed enum all agree; near-misses like `"claude-cli "` raise `ConfigError`.
- `llm.summarize` has no caller in this release — `[notes]` is validated but unused, matching the plan's "honoured by `vocalize notes` from 0.14.0".
- The Swift recorder is untouched: `git diff origin/main..HEAD -- vocalize/recorder/` is empty.
- No file read in this lens contained text addressed to an AI; the prompt constants found (`CLEANUP_PROMPT`, `VERBATIM_PROMPT`, `DATA_BOUNDARY`, `SUMMARY_PROMPT_TEMPLATE`) are the product's own outbound prompts, not instructions to a reviewer.

### auth._SecurityKeychain and auth.py store/read/delete/validated_on

- Key never in argv on any path: store emits `security -i` with the secret only on stdin; read emits `find-generic-password -s ... -a ... -w` with no secret on the command line at all.
- Key never in an environment variable: `_call` passes no `env=`; the anthropic key reaches only the `x-api-key` HTTP header, and `_claude_env` actively strips it from the claude child.
- `security` does not echo the secret back on any failure mode tried (unknown command, bad flag) — confirmed against the real tool, both on stderr and in the usage block.
- Store-path errors are scrubbed regardless: `AuthError(scrub(str(exc), key))` with `from None`, and the portal's login/test routes scrub every message and drop `__cause__` too.
- `security -i`'s return code is not trusted alone — a probe against a real throwaway keychain showed rc 0 with empty stderr while writing to the wrong keychain, confirming why the mandatory read-back exists.
- Exit code 44 is the real not-found contract, confirmed against the real tool (`errSecItemNotFound`/-25300).
- `comment()` never asks for the secret (no `-w`), and its regex correctly leaves `validated_on` at `None` for an item with no comment.
- A timeout on a blocked keychain becomes `SecurityKeychainError` → `("error", ...)`, never a traceback — `subprocess.TimeoutExpired` is caught by `_call`'s `(OSError, subprocess.SubprocessError)`.
- `_check_shape` blocks every line-breaking and non-printable character tried (newline, CR, tab, NUL, VT, ESC, U+0085, U+2028, NBSP, zero-width space, BOM, plain space); only `"`, `\` and printable non-ASCII pass, and the first two are refused one layer down on macOS.
- The 512-char cap is enforced before any network call, comfortably above every supported key format, and is refused before `validate_key` runs.
- Non-macOS / missing-`security` fallback to `keyring>=25` (a hard dependency) is correct, so the `ImportError` path in `delete_password` cannot fire in a supported install.
- Delete is decided by a read-back, not by the exception: a still-present key after delete raises "the key is STILL stored"; an unreadable keychain raises "could not confirm" rather than claiming removal.
- `auth status` and `/api/state` never print a whole key — both route through `masked()`, pinned by an existing test.
- The validation stamp is built from the clock and fixed constants only; the only externally supplied field on the `security -i` line is the key itself.
- Baseline green before and after probing: `tests/test_auth.py` 57 passed (pre-fix); `ruff check` clean; `git status --porcelain` empty before the fixer's edits.

### portal auth routes (login / test / remove / keys state) and the Keys tab

- Token, Host and Origin gates all hold on the new anthropic-slot routes: no token, token in URL, wrong Host (including duplicate-Host and absolute-form-target tricks), wrong/`null` Origin, and a browser-shaped simple-request CSRF all 403 with the keychain untouched.
- Disallowed methods (GET/PUT/DELETE/HEAD/OPTIONS/PATCH/TRACE) on the new routes all answer 405 with full security headers, no CORS grant.
- Slot-name path tricks (`../..`, percent-encoding, case, trailing slash) are all 404 before any handler runs; the submitted name is never echoed.
- `_slot_or_404`'s surface is exactly `auth.PROVIDER_USERNAMES`, and every route key carries the same token/Host/Origin checks as the literal ones in `ROUTES`.
- Body-shape and size gates hold ahead of any keychain or network call: a non-object body, an oversized body, an over-512-char key, and control characters (including U+202E) are all refused before `probe_keychain` or any provider call.
- Keychain failure modes are reported honestly, not silently: a read error renders every slot as "error" (not a false "not found"); a delete refusal reports "the key is STILL stored" and leaves it in place; a non-keyring delete error is a 400, never a false success.
- The test route stores nothing, on a valid key, an invalid key, and an unreachable-provider result.
- A canary key driven through login, two test calls (one with a key-echoing provider error), three state polls, and a remove — zero bytes of the canary in any response body, header, stdout, or stderr, and no file under an isolated HOME/XDG carries it.
- Security headers (CSP with `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, `Cache-Control: no-store`) present on every new-route response, success and error alike.
- The unplanned-exception path answers a fixed 500 with no traceback and logs nothing — no query string or exception text can reach the page or the terminal from these routes.
- No DOM sink exists in the Keys tab: no `innerHTML`/`eval`/`document.write`; a hostile keychain comment string rendered through `textContent` is inert; the session token lives only in `sessionStorage`, never the key.
- The validation stamp never touches the secret (`comment()` reads without `-w`), and is empty for an environment- or `.env`-sourced key.
- Masked previews are `auth.masked()` output only, with the eight-character floor from the 0.11.0 review still in force.
- A key test is a real, user-initiated HTTPS send to a hardcoded provider endpoint with zero stderr output, considered against the egress invariant and not reported — it names the provider on the button and reads no response body, the same shape `auth login` has had since 0.9.
- Suite: `tests/test_portal.py -k "anthropic or remove or test_without or login"` 99 passed; portal + portal_assets + auth combined 598 passed under an isolated HOME.
- No text addressed to an AI was found in any file read for this lens.
