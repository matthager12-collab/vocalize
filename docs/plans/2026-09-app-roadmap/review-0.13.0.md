## What each lens checked and found clean

The absence of a finding is only evidence if the check is written down. Each bullet below is a check a lens actually ran, against the real code, a real fake-tool harness, or the built test suite — never a reading of the code alone.

### spawn-and-text

- No shell anywhere in the slice: `grep` for `shell=True` / `os.system` / `os.popen` across `vocalize/*.py` and `vocalize/local/*.py` returns nothing; every tool call in `app.py` goes through `_run()` (app.py:125-134) as a list argv with `check=False`, `capture_output=True`, `text=True` and a timeout.
- Every argv element in `app.py` is a module constant or a constant-derived path — bootout, bootstrap, kickstart, tccutil, defaults delete, pgrep and launchctl list (app.py:148-176, 225). No user text, no file-derived text and no `app.status` value ever reaches an argv.
- `tccutil` argv names the bundle id: `[TCCUTIL, "reset", "Accessibility", LABEL]` (app.py:168), not a bare `tccutil reset Accessibility`, which would drop every application's grant on the machine.
- `tccutil` runs only on build status "rebuilt" (cli.py:1411-1414); "built" and "current" never reach it. Pinned by `tests/test_app_cli.py::test_tccutil_runs_only_when_the_bundle_was_rebuilt`.
- `launchctl bootout` targets `gui/<uid>/<label>` (app.py:141-148), never the bare `gui/<uid>` domain, which would tear down the whole login session.
- `app.status` is parsed against a closed vocabulary and nothing else escapes: an ANSI escape in the vocalize path, a U+202E bidi override, a relative path, a >512-char path and an invented hotkey name (`"failed:rm -rf /"`) all read "unknown".
- `app.status` cannot poison the two fields it does not own: a file containing `"bundle: current"` and `"agent: loaded"` leaves both keys untouched, because `read_status()` only accepts its four known keys and `status_dict()` splats it after bundle/agent (app.py:296-309).
- `app.status` oversize (>64 KiB), missing, unreadable and symlinked-at-the-final-component all read "unknown" for all four fields; pinned by `tests/test_app_cli.py:483` and `:489`.
- `str.isprintable()` on the vocalize path value excludes category Cf, so bidi/format-character injection into terminal output and into the portal's JSON is blocked, not just C0 control characters.
- `agent_state()` parse rule holds against realistic launchctl fixtures: PID line (both the plist and column forms) → loaded, documented "Could not find service" → not running, and everything else — a dict with no PID, unparsable stdout, a non-zero exit with other text, a missing binary, a timeout — → unknown.
- `bundle_state()` is read-only — `bundle_path().is_dir()` plus `install.bundle_is_current()`, never `build_bundle` (app.py:193-206). Pinned by `tests/test_app_cli.py::test_status_never_builds_anything`, so readiness, the doctor and the portal poll cannot compile Swift as a side effect.
- `write_plist()` opens with `O_CREAT|O_WRONLY|O_TRUNC|O_NOFOLLOW` and chmods 0644 afterwards (app.py:340-343), so a planted symlink at the plist name fails and a tight umask cannot leave the file at the wrong mode. Pinned by `tests/test_app_cli.py:221`.
- Install ordering is build → (tccutil only if rebuilt) → write plist → bootout → bootstrap, with the bootout failure ignored and the bootstrap failure raising a `ClickException` that names the command. Pinned by `tests/test_app_cli.py:232` and `:244`.
- Uninstall scope is six named paths, never a directory sweep, and refuses to `rmtree` through a symlink via `is_dir()/is_file()` + `not is_symlink()`. Pinned by `tests/test_app_cli.py:556` and `:589`.
- Nonce quality and exposure: `secrets.token_hex(8)` is a 64-bit CSPRNG value (dictate.py:388), minted once at the claim and carried through unchanged by `_write_session`; it is never printed, logged, put in a notification, or exposed by the portal — it only ever reaches the 0600 session file.
- `_read_session` ignores unknown keys, so the new `state`/`nonce` fields (and anything a later release adds) cannot break an older reader (dictate.py:436-445).
- `clip`'s credential refusal sets `exit_code = 3` on the `ClickException` instance without a new exception class, and echoes no part of the clipboard (cli.py:459-470).
- Full run: `pytest tests/test_app_cli.py tests/test_app_build.py tests/test_dictate.py tests/test_readiness.py tests/test_portal.py -q -p no:cacheprovider` → 781 passed; `ruff check vocalize hooks tests` → All checks passed.

### launchctl-tccutil

- `tccutil` is unreachable on a non-rebuild and always runs before the agent is loaded again on a rebuild, with the exact argv order pinned by `tests/test_app_cli.py::test_tccutil_runs_only_when_the_bundle_was_rebuilt`.
- `bootout` always precedes `bootstrap`, with the exact argv including `gui/<uid>`; pinned by `tests/test_app_cli.py::test_install_boots_out_before_it_bootstraps`.
- A bootstrap failure after the plist is written leaves recoverable state: it raises a `ClickException` naming the command, the plist and bundle stay on disk, `RunAtLoad` picks them up at next login, and a re-run of install is idempotent (`build_bundle` answers "current", so `tccutil` is not re-run).
- The plist is written only into `~/Library/LaunchAgents`, built from the fixed `LABEL` constant; no input reaches the path.
- Plist mode is 0644 even under a tight umask, verified under `umask 0077`; plist keys match the closed decision exactly, compared against a literal dict.
- Uninstall removes exactly the six named paths and nothing beside them — a recorder bundle, another `~/.cache/vocalize` file, and an unrelated LaunchAgent all survive.
- A symlink at the bundle path cannot make `rmtree` walk elsewhere; a symlinked `~/Library/Application Support/vocalize` redirects install/uninstall but with no blast radius beyond the two names they own.
- `defaults delete` argv is fixed from constants; `restart` uses `kickstart -k` against `gui/<uid>/<label>` and nothing else.
- `status` never builds — `tests/test_app_cli.py::test_status_never_builds_anything` asserts the fake toolchain recorded zero calls after the source moved on.
- Every tool call is a list argv with an absolute path, `check=False`, `capture_output=True`, `text=True`, and no shell; `launchctl list` is read conservatively — a parse failure or an unrecognised exit code is "unknown", never "not running".
- The app source and Info.plist template ship in the wheel (`pyproject.toml:47-48`), the same mechanism the 0.12.0 recorder already relies on.
- `APP_SPEC`'s fields are pinned literally (source, template, entitlements=None, Vocalize.app, vocalize-app, AppKit+Carbon, stamp ".app", stamp_version 1, noun "app").
- Suite and lint at review time: `tests/test_app_cli.py` + `tests/test_app_build.py` + `tests/test_readiness.py` — 120 passed; `ruff check vocalize hooks tests` — All checks passed.

### untrusted-status

- `app.status` hostile inputs all return the four unknowns with no exception: missing file, 2 MB file (capped, memory bounded), symlink at the path, non-UTF-8 bytes, lines with no colon, 10,000 lines, a directory at the path.
- The vocalize-path guard rejects a relative path, an ANSI escape, a 600-character path and an empty value; interior spaces are accepted, which is correct for macOS and safe because the value is only printed and compared, never executed.
- Portal rendering of the untrusted path has no sink: `vocalize/assets/portal.js` contains no `innerHTML` and no reference to the state's `app` key, so the path in `/api/state` reaches no DOM sink today.
- Readiness rows carry only normalised words: `_app_row`, `_app_agent_row` and `_accessibility_row` (readiness.py:286-318) return string literals in every branch — no value read from `app.status` is ever placed in a `Row`.
- `hotkeys` vocabulary matches the Swift writer exactly (`dictate|speak|stop|settings`, optional `:taken`); an arbitrary payload such as `"failed:$(rm -rf /)"` reads "unknown".
- Python never writes a fourth session state word — the only `_write_session` call sites are "recording" and "transcribing", plus "starting" minted at the claim — all three are cases the Swift `iconState` switch recognises, so the `.unrecognised` attention icon can never be triggered by this CLI.
- `_read_session` ignores the new keys safely, reading only `dir` and `started`; the `_is_workdir` gate still enforces prefix, tmp root, uid and 0700 on the untrusted dir.
- The session write is symlink-safe (`O_CREAT|O_WRONLY|O_TRUNC|O_NOFOLLOW` at 0600), and the dir-mismatch guard stops a later press's record from being overwritten by an older take.
- `clip`'s exit 3 has exactly one origin — `refusal.exit_code = 3` is the only exit_code assignment in `vocalize/` and `hooks/`, with no other `sys.exit(3)`/`ctx.exit(3)` anywhere.
- No tool ever runs through a shell; every `_run()` call site passes a list argv built from module constants and the fixed `LABEL`, with `check=False`, `capture_output=True` and a timeout.
- `write_plist` is symlink-safe and mode-correct; `agent_state` never guesses — a tool that would not run, an unrecognised exit code and unparsable output all return "unknown"; `bundle_state` is read-only and cannot be hung by a FIFO planted at the bundle binary path (`install.bundle_is_current` requires `binary.is_file()` before hashing).
- Suite green at review time: `tests/test_app_cli.py`, `tests/test_dictate.py`, `tests/test_readiness.py` → 255 passed; `ruff check vocalize hooks tests` → All checks passed.
